# Agents — ταίριασμα δωματίων και αναβάθμιση τιμολόγησης

Ημερομηνία: 2026-09-29. Κατάσταση: σχέδιο εγκεκριμένο προφορικά (σκορ + ελληνική αιτιολόγηση,
αυτόματο τρέξιμο ανά scrape, fallback στο στατιστικό, badge πηγής). Προϋπόθεση: το
`ANTHROPIC_API_KEY` υπάρχει πλέον στο `.env` (2026-09-29). Βάση: το `main` μετά τη
συγχώνευση των rate plans (τα δύο μέρη μοιράζονται τα δεδομένα πλάνων).

## Μέρος Α — Matching agent (νέο)

### Α.1 Πότε τρέχει

- Αυτόματα στο τέλος κάθε ολοκληρωμένης εργασίας `competitor_search`, best-effort όπως οι
  ειδοποιήσεις τιμής (αποτυχία δεν αγγίζει ποτέ την εργασία)· μόνο όταν υπάρχει κλειδί.
- Χειροκίνητα: `POST /api/v1/agents/room-matches` `{scrape_job_id, owned_room_type_id}` —
  το UI το καλεί με κουμπί «Επανεκτίμηση ταιριάσματος» όταν αλλάξει το δωμάτιο αναφοράς.
- Όρια: ημερήσιο πλαφόν ανά λογαριασμό `MAX_DAILY_ROOM_MATCH_RUNS_PER_ACCOUNT` (default 30),
  timeout `ANTHROPIC_TIMEOUT_SECONDS` (υπάρχον). Idempotency: αν υπάρχουν ήδη γραμμές για το
  (job, δωμάτιο αναφοράς) δεν ξανατρέχει αυτόματα (το χειροκίνητο τις αντικαθιστά).

### Α.2 Είσοδος/έξοδος (παράλληλα τμήματα ανά εργασία)

Είσοδος: το δωμάτιο αναφοράς (όνομα, κατηγορία, δείγμα τιμής, παροχές) + ανά κατάλυμα του
job τα δωμάτιά του από τα packages (ονόματα, κατηγορία, `max_persons`, παροχές δωματίου,
σύνοψη πλάνων: εύρος τιμών, κλάσεις ακύρωσης, Genius). Μοντέλο: `claude-sonnet-5-5`
(ρυθμιζόμενο `ANTHROPIC_MATCHING_MODEL`), δομημένη έξοδος (`client.messages.parse` /
`output_config.format`), system prompt στα ελληνικά. Σχήμα εξόδου ανά δωμάτιο ανταγωνιστή:
`{property_id, room_type, score: int 0-100, category_match: "same"|"similar",
reasoning: string ≤ 160 χαρ. στα ελληνικά}`.
Όρια κλήσης (απόφαση ιδιοκτήτη 2026-09-30): το AI βαθμολογεί ΟΛΑ τα δωμάτια ανταγωνιστών
του job, χωρίς όριο ανά κατάλυμα. Οι υποψήφιοι μπαίνουν σε ντετερμινιστική σειρά (ίδια
κατηγορία πρώτα, μετά φθηνότερη τιμή, μετά ids) και στέλνονται σε τμήματα των 40 που
βαθμολογούνται παράλληλα (έως 8 ταυτόχρονα: μια τυπική εργασία 4-6 τμημάτων τελειώνει σε
έναν γύρο, περίπου στον χρόνο ενός τμήματος). Όριο ασφαλείας 600 μοναδικά δωμάτια
(φρένο κόστους/καθυστέρησης, πρακτικά δεν πιάνεται: μια εργασία 89 ξενοδοχείων στο Φαληράκι
έχει ~150-250)· όσα μένουν εκτός κρατούν το στατιστικό σκορ. Το στατιστικό σκορ είναι ΜΟΝΟ
εφεδρεία, για τμήμα που αποτυγχάνει ή δωμάτιο που παραλείπει το μοντέλο (θεμιτό «μερική»).
Τυπικό κόστος ~0,15-0,40 $ ανά scrape 89 ξενοδοχείων. Έξοδος έως 8000 tokens ανά τμήμα·
δικό του timeout `ANTHROPIC_MATCHING_TIMEOUT_SECONDS` (default 120") ανά τμήμα· έως 1
επανάληψη SDK ώστε το post-scrape hook να μην μπλοκάρει. Μη ακέραιο score από το μοντέλο
στρογγυλοποιείται και ψαλιδίζεται αντί να ρίχνει όλο το run.

### Α.3 Αποθήκευση — migration `20260930_0026`

Νέος πίνακας `roomrate_room_matches`: `id, account_id, scrape_job_id, owned_room_type_id,
property_id, room_type, score NUMERIC(5,1), category_match VARCHAR(10), reasoning TEXT,
model_version VARCHAR(60), created_at` — unique
`(scrape_job_id, owned_room_type_id, property_id, room_type)`, upsert σε αντικατάσταση.
Audit: εγγραφή ανά run σε νέο ελαφρύ πίνακα `roomrate_agent_runs`
(`id, account_id, scrape_job_id, kind='room_matching', status ok|error, model, error_message,
created_at`) — ό,τι χρειάζεται για να δούμε γιατί «δεν βγήκε AI εκτίμηση».

### Α.4 Ανάγνωση/UI

- `/api/v1/competitors?match_room=true`: αν υπάρχουν γραμμές agent για (job, δωμάτιο
  αναφοράς), τα `match_score` των αντίστοιχων πακέτων/δωματίων προέρχονται από εκεί, αλλιώς
  από το σημερινό στατιστικό. Νέα πεδία (διόρθωση 2026-09-30: το endpoint επιστρέφει σκέτη
  λίστα, άρα ΑΝΑ ανταγωνιστή): `Competitor.match_source: "agent"|"statistical"` και ανά
  πακέτο `match_reasoning: string|null`. Μικτές απαντήσεις είναι θεμιτές· το badge δείχνει
  «Εκτίμηση AI» (όλα agent), «Εκτίμηση AI (μερική)» (μικτά), «Στατιστική εκτίμηση» (κανένα).
  Slider/ταξινόμηση/κλίμακα: αμετάβλητα.
- UI: badge μία φορά στο μπλοκ «Ταίριασμα δωματίου» — «Εκτίμηση AI» ή «Στατιστική εκτίμηση»
  (ποτέ ψευδής πηγή)· στην κάρτα, η αιτιολόγηση ως μία γραμμή κάτω από το chip ταιριάσματος·
  κουμπί «Επανεκτίμηση ταιριάσματος» με κατάσταση εκτέλεσης. Ελληνικά, μηδέν emoji.

### Α.5 Αποτυχίες

Οποιοδήποτε σφάλμα (κλειδί, timeout, μη έγκυρη έξοδος, quota) → καμία γραμμή, audit row
`error`, το UI δείχνει «Στατιστική εκτίμηση» — ποτέ σφάλμα στον χρήστη από αυτό το μονοπάτι.
Και οι παραλείψεις (quota, χωρίς κλειδί, ήδη υπάρχουσες γραμμές) γράφουν audit row
`skipped` με την αιτία, ώστε το «γιατί δεν βγήκε AI εκτίμηση» να απαντιέται πάντα
(review 2026-09-30).

## Μέρος Β — Pricing agent (αναβάθμιση του υπάρχοντος)

1. **SDK/μοντέλο:** default μοντέλο `claude-opus-5-5` (ρύθμιση `ANTHROPIC_MODEL`, χωρίς
   αλλαγή alias), κλήση χωρίς παράμετρο `thinking` (πάντα ενεργή στο μοντέλο), δομημένη
   έξοδος με το surface που υποστηρίζει το ΕΓΚΑΤΕΣΤΗΜΕΝΟ SDK 0.115.0 (`messages.parse`·
   επιβεβαίωση ονομάτων παραμέτρων από τις signatures του εγκατεστημένου πακέτου, όχι από
   μνήμη). Η αναβάθμιση του pin σε anthropic 1.x ΑΝΑΒΑΛΛΕΤΑΙ (κοινό global env με όλα τα
   worktrees — ξεχωριστή μελλοντική εργασία). Τα υπάρχοντα tests με fake client
   προσαρμόζονται· καμία αλλαγή σε guardrail ±20%, cache (με run id), quota 50/ημέρα, audit.
2. **Πλουσιότερο context:** στο advisor payload ανά ανταγωνιστή προστίθενται απόσταση,
   `category_match`, φθηνότερη τιμή στην ίδια κλάση ακύρωσης και ένδειξη Genius· στο
   στατιστικό μπλοκ το `stats_scope` όπως ισχύει. Το system prompt παραμένει ελληνικό.
3. **Live επαλήθευση:** μετά το merge, ένα πραγματικό αίτημα σύστασης (κόστος λίγα λεπτά)
   με τον ιδιοκτήτη παρόντα: έλεγχος ότι `source: "agent"` εμφανίζεται, ελληνική αιτιολόγηση,
   εύρος λογικό, χρόνος < 30".
